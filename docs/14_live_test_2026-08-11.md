# Live manual LCMV test — 2026-08-11

## Scope and conclusion

This run is evidence for one fixed-geometry, 50 dB jammer-attenuation test. It is
not proof that LCMV will retain PVT for every jammer position, power, or on/off
cycle.

The clean physical-jammer-on interval with one requested MUSIC source passed:

- all 26 one-second receiver snapshots remained `FIX`;
- the eight stable GPS channels recorded zero `cycle_slip` flags and zero sample
  counter resets;
- carrier-phase event residuals remained inside the ordinary adjacent-sample
  distribution;
- aggregate covariance-excess jammer suppression was 19.71 dB for the applied
  weights; and
- total beamformer-output reduction relative to uniform combining was 4.22 dB
  median. This is not the same as jammer-only suppression.

Changing the requested MUSIC source count from one to two did not improve the
run. The displayed primary MUSIC peak changed to the bladeRF direction, fallback
occurred, C/N0 became less stable, and aggregate covariance-excess suppression
fell to 3.61 dB. Keep one requested source for this fixed two-emitter laboratory
scene until the source-count and peak-association logic is redesigned and
retested.

Manual robustness testing is the next stage. Automatic LCMV detection,
selection, or retargeting must not be enabled until the manual pass gates in
this document have been met.

## Suppression quantities and equations

Let the calibrated four-channel input be `x[n]`, its covariance be
`R = E{x x^H}`, uniform weights be `u = [1,1,1,1]^T`, and the applied weights be
`w`.

Uniform-combiner and LCMV output powers are:

```text
P_uniform = u^H R u
P_output  = w^H R w
```

The GUI's generic total output reduction is:

```text
total_reduction_db = 10 log10(P_uniform / P_output)
```

“Versus uniform” means that the denominator is the actual beamformed output and
the numerator is what the output power would have been if all four calibrated
channels had simply been added with equal phase and amplitude weights. This
number includes changes to wanted GNSS, bladeRF, jammer, and noise. It is not
jammer-only suppression.

The noncoherent calibrated four-input power sum is:

```text
P_four_input_sum = trace(R) = sum_i E{|x_i|^2}
reduction_vs_four_inputs_db = 10 log10(P_four_input_sum / P_output)
```

For jammer-excess suppression, freeze the jammer-off covariance `R_arm` when
LCMV is armed, then form the positive-semidefinite projection:

```text
Delta_R_plus = PSD_projection(R_current - R_arm)
P_jammer_uniform = u^H Delta_R_plus u
P_jammer_output  = w^H Delta_R_plus w
```

Across equal-duration records, the aggregate estimate is:

```text
jammer_suppression_db =
    10 log10(sum(P_jammer_uniform) / sum(P_jammer_output))
```

It may be described as jammer-only only inside an explicit physical-jammer-on
marker window with an otherwise unchanged bladeRF scene.

## Smooth weight application

The configured transition is 1.0 s. At 4 MS/s and 32,768 samples per processing
chunk, that becomes 123 chunks, approximately 1.008 s. Each chunk applies:

```text
w_k = (1 - alpha_k) w_start + alpha_k w_target
alpha_k = k / 123
```

Target updates do not preempt and restart an active transition. In this live
run, transition diagnostics contained 31 distinct progress values from 0 to
0.99187. The largest target endpoint difference was 3.9167 complex-weight units,
while the largest computed next-chunk step was 0.03627. The endpoint therefore
was not applied as one immediate 3.9-unit jump.

Smoothing reduces abrupt combined-stream amplitude and carrier-phase steps. It
does not guarantee tracking continuity, and excessive smoothing can lag a moving
jammer. Manual motion tests must determine the acceptable transition time.

## Ideal steering versus measured dominant U1

Both choices use one covariance LCMV solver:

```text
w = R^-1 C (C^H R^-1 C)^-1 f
```

The active method in this run was `covariance_lcmv_ideal`. The measured dominant
eigenvector U1 method was calculated only as a diagnostic candidate and was not
applied.

During the clean jammer-on segment, ideal-vector versus measured-U1 coherence
was approximately 0.85 and their principal-angle mismatch averaged 31.56
degrees. This explains the apparent contradiction between an algebraic ideal
null near -300 dB and only about 11.24 dB predicted reduction of the measured U1
by the active ideal weights.

The near -300 dB value is floating-point evaluation of the exact vector
constraint `|w^H a_ideal|`; it is not measured over-the-air suppression. The real
jammer has steering-vector error, calibration error, finite covariance data,
multipath, noise, and possibly frequency-dependent response.

The measured-U1 diagnostic candidate also produced a near-numerical-zero U1
constraint, but it was not robust enough to promote automatically:

- it was valid in 23/23 clean one-source records;
- its average weight norm was 4.19 and average white-noise gain was 12.36 dB;
- after the two-source change it was invalid in 30/80 records, mainly because
  its weight norm exceeded the safety limit; and
- U1 means only “dominant covariance direction.” Without a jammer, or when
  association swaps, U1 can be the wanted bladeRF/GNSS scene.

Therefore measured-U1 must be tested as a separate manually selected covariance
LCMV input. It must not silently replace the ideal method or become an automatic
jammer detector.

## Required manual robustness tests before automation

Run ideal-steering LCMV and measured-U1 LCMV as separate fresh experiments using
the 30-minute file. The user alone turns the physical jammer on/off and moves it.
For each method:

1. Start bladeRF first and acquire stable GNSS PVT.
2. Arm manual LCMV while the jammer is physically off and freeze the desired
   bladeRF reference.
3. Complete at least five marked jammer on/off cycles at fixed geometry.
4. Repeat at multiple jammer positions, with holds of at least 30 to 60 s.
5. Keep requested MUSIC source count at one for the primary test. Test two-source
   behavior separately; do not mix it into the method score.
6. Test weight-transition durations separately rather than changing them within
   one scored interval.

Each interval must log and pass:

- current PVT for 100% of the marked jammer interval;
- at least four used observations, with the present seven preferred;
- zero cycle slips and zero tracking-counter resets;
- monotonic TOW and continuous valid symbols;
- no multi-satellite carrier-phase jump outside the baseline residual
  distribution;
- per-PRN C/N0 transient, minimum, recovery time, and post-recovery level;
- positive, repeatable aggregate jammer-excess suppression;
- completed weight ramps without fallback oscillation; and
- for measured-U1, acceptable weight norm, white-noise gain, candidate rejection
  rate, and stable jammer/wanted association.

## Automation gate and later design

Do not implement or enable automatic LCMV yet. Automation starts only after both
manual method reports exist and at least one method passes the gates above
repeatedly.

The later automated controller should be an explicit state machine:

1. `REFERENCE`: require healthy PVT/tracking and learn/freeze the jammer-off
   covariance and bladeRF protected direction.
2. `ARMED`: monitor covariance-excess and spatial consistency without applying a
   null.
3. `JAMMER_CANDIDATE`: require persistence and hysteresis; reject peaks inside
   the protected-direction guard.
4. `TRANSITIONING`: schedule bounded weight changes through the existing smooth
   ramp; do not restart a ramp for every covariance snapshot.
5. `ACTIVE`: update no faster than a tested rate and continue PVT/carrier safety
   checks.
6. `HOLD_OR_FALLBACK`: latch the last proven-safe weights for short detection
   dropouts; return smoothly to uniform only under a defined safety condition.

Automatic method choice must use measured performance and safety gates. A deep
algebraic vector null alone is not a promotion criterion.

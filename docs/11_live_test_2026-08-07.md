## What the live test proved

- The covariance LCMV solver satisfied its authored ideal preserve and null constraints numerically, with residuals around 1e-17 in a captured active update.
- The ideal steering vector at the frozen bladeRF angle did not match the actual OTA bladeRF spatial signature well enough. Mathematically preserving that ideal vector still cost approximately 7-9 dB of GNSS C/N0 with no jammer.
- A non-preserve MUSIC angle by itself is not valid jammer evidence. The old run-state score false-triggered on angle/vector changes.
- Abrupt and repeatedly changing covariance weights correlated with substantial C/N0 movement.
- Total output reduction (one captured value was 19.73 dB versus uniform) is not jammer-only suppression and cannot be reported as such.
- The best healthy result in these intervals was the uniform jammer-off baseline, approximately 49.4-49.5 dB-Hz with current PVT. No tested LCMV interval matched it.

## Code changes made after the observation

These changes are on disk but were not loaded into the live process used above:

- One shared covariance LCMV solver remains; there is no covariance-free implementation.
- The selectable ideal-angle-only bladeRF preserve mode was removed.
- The product now associates a fresh measured healthy U1 with the stable live bladeRF angle cluster and freezes that measured vector/covariance at enable time.
- Enabling LCMV arms uniform output first.
- Activation requires both an input-power rise and a generalized covariance-mode rise; angle alone is explicitly forbidden.
- Jammer detection latches until LCMV is disabled.
- Target weights use a one-second complex linear chunk ramp. Every ramp point preserves the same measured-U1 complex response because both endpoints obey that equality constraint.
- GUI states distinguish ARMED, ACTIVATING, ON/jammer-latched, and safety FALLBACK.
- Automated result after the changes: 240 tests passed, 1 hardware-dependent test skipped.
